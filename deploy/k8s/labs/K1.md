# K1 — Images

**Goal:** get our three images into the cluster through a local registry, with immutable tags.

## What this repo teaches here
- `deploy/k8s/scripts/registry-up.sh` — a plain `registry:2` container on `127.0.0.1:5000` (never `0.0.0.0`: Docker-published ports bypass ufw).
- `deploy/k8s/host/registries.yaml` — tells k3s's containerd that `localhost:5000/*` is a plain-HTTP registry.
- `deploy/k8s/scripts/images.sh` — builds with the repo root as context, tags `localhost:5000/<svc>:<git sha>`, pushes; refuses `:latest`.
- `base/kustomization.yaml` `images:` + `apply.sh` — manifests say `localhost:5000/go-server`; the tag is pinned at deploy time without editing files.

## Concepts
- **Image reference**: `registry/repository:tag` or `...@sha256:digest`. A tag is a movable pointer; a digest is the content hash.
- **imagePullPolicy**: `IfNotPresent` (our choice — safe because tags never move), `Always` (contact the registry every start), `Never`.
- **Two image stores**: Docker Engine has one, k3s's containerd has *another*. The registry is the bridge between them.

## Try it
```bash
make registry-up
make images                                   # TAG defaults to the git short sha
curl -s localhost:5000/v2/_catalog            # {"repositories":["dashboard","fastapi-server","go-server"]}
curl -s localhost:5000/v2/go-server/tags/list # {"name":"go-server","tags":["a1b2c3d"]}
make k8s-up OVERLAY=dev                       # (K2 explains what this creates)
sudo k3s crictl images | grep localhost:5000  # now cached in containerd too
kubectl -n bench get pods -o jsonpath='{range .items[*]}{.spec.containers[0].image}{"  "}{.status.containerStatuses[0].imageID}{"\n"}{end}'
```
The last command shows tag (what you asked for) next to digest (what actually runs).

## Break it on purpose
1. Deploy a tag that doesn't exist: `TAG=typo123 ROLLOUT_TIMEOUT=30s make k8s-up OVERLAY=dev` (apply succeeds, the rollout wait fails).
2. `kubectl -n bench get pods` → `ErrImagePull`, then `ImagePullBackOff`.
3. `kubectl -n bench describe pod -l app.kubernetes.io/name=go-server | sed -n '/Events/,$p'` → `Failed to pull image "localhost:5000/go-server:typo123": ... not found`. Note the back-off delay growing (10s, 20s, 40s… up to 5 min).
4. The *old* pods keep serving: `maxUnavailable: 0` means a broken new ReplicaSet never takes capacity away.

**Recover:** `make k8s-up OVERLAY=dev` (correct tag) — or `kubectl -n bench rollout undo deploy/go-server`.

## Check yourself
<details><summary>Why are immutable tags safer than <code>:latest</code>?</summary>

With `:latest`, two nodes (or two restarts of the same node) can run different code under the same name, rollbacks are impossible (the old content has no name anymore), and you can't tell from the manifest what is deployed. Benchmarks recorded against `:latest` are not reproducible. A git-sha tag ties every result to a commit; `IfNotPresent` is then always correct. (Strictest: pin by digest.)
</details>

<details><summary>Why can't k3s just use the image I built with <code>docker build</code>?</summary>

k3s uses its own containerd, separate from Docker's image store. Options: push to a registry (ours), `docker save | sudo k3s ctr images import -`, or run k3s with `--docker`. The registry mirrors how real clusters work.
</details>

<details><summary>Why build images on the Ubuntu box rather than the Mac?</summary>

The Mac builds arm64 images; the server is amd64. A cross-arch image fails with `exec format error` (or runs emulated and slow). `images.sh` warns when run on macOS.
</details>
